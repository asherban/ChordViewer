# M6 Library and Practice verification

Verification date: 2026-09-23. Work is on `codex/m6-library-practice` above the M5 baseline. This milestone is accepted locally; there is no push, pull request or deployment. The [execution plan](../architecture/m6-execution-plan.md) and [product contract](../architecture/library-practice.md) define the behavior. M7 is the next local validation milestone.

## Delivered behavior

The backend adds account-owned Library metadata and recoverable Trash through an additive migration. A bounded list includes real first-bar chord labels rather than full scores; the authenticated open action updates Recent order. The 100-sheet quota includes Trash. Revision checks cover metadata, duplicate, Trash and restore, including a selected dirty draft whose list summary has advanced elsewhere. Both clients provide search, content/tutorial filters, sorting, favorites, Draft designation, rename, duplicate and restore, with guarded reload for conflicts.

Both clients provide read-only Practice over the in-memory chart: Manual navigation and an optional fresh-gesture On match mode, selected chord/bar indication, live held notes beside completed-gesture comparison, size and notation controls, hidden tutorial, separate Edit/Practice bookmarks, and a derived −12 to +12 semitone transposition that never changes the authored score. YouTube embeds load only after a deliberate Play action and can be stopped or hidden without affecting the chart.

## Limits

Bookmarks are local to a web tab (`sessionStorage`) or the current Android ViewModel process and do not sync across devices. Unsaved drafts are not durable across reload/process death; recovery, backup restoration, concurrent-edit policy and repeated resource-usage validation belong to M7. Physical USB/Bluetooth controllers and tablet hardware are not covered by the LoopBe/AVD acceptance. The release Android client remains unconfigured for a deployed HTTPS API. The YouTube provider controls individual videos and availability; the official demo played locally, but one other video reported unavailable. The native playback capture shows a start and a buffering frame, not sustained uninterrupted playback. The Vite large-chunk advisory and Android lint style suggestion remain visible, with no build or lint errors.
