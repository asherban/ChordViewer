# Library and Practice contract (M6)

Library is an account-owned collection of at most 100 sheets, including recoverable Trash. A list response contains metadata and at most four actual chord labels from the first bar of each score; it never contains full notation. Both clients load the complete score when opening a sheet. GET is read only. An authenticated, origin-guarded POST to `/api/v1/sheets/{id}/open` records an intentional open for Recent sorting. Rename, favorite and Draft designation atomically compare the current revision. Duplicate creates a fresh score ID and title. Moving to Trash increments the revision and blocks score writes until a guarded restore. Trash preserves the score and its tutorial; it does not free quota.

Favorite, Draft designation and recent-open updates leave any unsaved score, editor cursor and undo history in memory. Rename is a guarded change to the saved title and needs confirmation before discarding a dirty local title/score. A confirmed Reload replaces the local draft with the authoritative saved score. A delayed list response cannot supersede a newer mutation. Account switches and sign-out invalidate late private responses.

Practice presents the in-memory authored score without saving or mutating it. Manual bar navigation is the default. The selected bar and chord are visible and selectable even when a bar has multiple chords; an empty bar has no implicit target. Optional On match advances after an ordered, completed physical-key gesture. It waits for all held keys to be released before rearming after a mode switch, dialog, API operation or MIDI reconnect. Sustain does not extend the gesture boundary. Comparison uses all valid identities in the shared chord vocabulary, with optional tones, enharmonic spelling and explicit slash bass checked by pitch class; unsupported symbols stay navigable manually. Live held notes and the last completed gesture are shown separately.

The Practice transposition is a validated derived score from −12 to +12 semitones. It moves chord roots/slash bass, key and melody pitches while preserving timing, IDs, rests, dots and ties. Invalid shifts report a reason and leave the authored score unchanged. Display lane, score size and tutorial visibility also remain presentation state. Edit and Practice positions are remembered separately per account and sheet: the web uses tab-scoped `sessionStorage`, while native Android keeps them in the current ViewModel process. They are not server-synced positions. Only the explicit Edit sheet action transfers the selected Practice position into Create. The MIDI editor does not arm itself during that transfer.

Tutorial playback uses the canonical YouTube embed in a dedicated player after an explicit tap. The score, MIDI and navigation work independently. Web uses `strict-origin-when-cross-origin` so the player receives the application origin as Referer, and unmounts the iframe when hidden. Android loads a bounded HTTPS embed using an installed-app-ID base URL, contains top-level WebView navigation on that app-ID page while the official YouTube iframe runs inside it, disables local file/content access and has no native JavaScript bridge. Both clients retain a user-initiated external YouTube link when embedding fails. The player has at least a 200 × 200 viewport and no app overlay on its controls.
